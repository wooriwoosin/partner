# 수파베이스 이전 계획

> 결정사항: **자체 로그인 유지**(아이디+비번) · **한글 컬럼명 유지** · **일괄수정은 테이블 에디터+CSV**
> · 기존 **`wooriwoosin` 프로젝트 안에 `partner` 스키마**로 설치 (새 프로젝트 불필요)

## 어디에 설치하는가 — 새 프로젝트를 만들지 않는다

무료 플랜은 계정당 활성 프로젝트 2개까지인데, 이미 두 개를 쓰고 계십니다.
그런데 **새 프로젝트가 애초에 필요 없습니다.** 프로젝트 하나는 Postgres 데이터베이스 한 벌이고,
그 안에 서로 격리된 영역(스키마)을 몇 개든 둘 수 있습니다.

```
wooriwoosin 프로젝트 (그대로 유지)
├── public 스키마   ← 지금 쓰시는 데이터 (손대지 않음)
└── partner 스키마  ← 업체 · 사용자 · 변경로그
```

스키마가 다르면 테이블 이름이 겹쳐도 충돌하지 않습니다. 무료 플랜 그대로 갑니다.

> 참고: 이 프로젝트 리전은 `ap-southeast-2`(시드니)입니다. 서울보다 왕복 150ms 정도 느리지만,
> 이미 데이터가 들어 있어 리전을 바꾸려면 프로젝트를 다시 만들어야 하므로 그대로 씁니다.
> 체감이 거슬릴 정도면 나중에 서울 프로젝트로 옮길 수 있습니다 (데이터는 CSV로 그대로 이동).

## 왜 옮기는가 — 지금 겪은 문제들이 구조적으로 사라진다

| 지금까지 겪은 사고 | 수파베이스에서는 |
|---|---|
| 헤더 행이 덮어써져 데이터가 뒤섞임 | 헤더 행이라는 개념이 없음 (컬럼은 스키마) |
| `계약서발송` 컬럼이 없어서 저장이 조용히 사라짐 | 없는 컬럼에 쓰면 **에러**가 뜸 |
| 빈 행 때문에 저장이 엉뚱한 행으로 밀림 | 행 번호가 아니라 `id`로 찾아 씀 |
| 중복 업체가 신규로 등록될 뻔함 | `소속원문` 유니크 제약으로 **DB가 거부** |
| `등록일`이 `Tue Aug 18 2026 00:00:00 GMT+0900`로 저장 | `date` 타입이라 형식이 하나뿐 |
| 변경로그 기록을 코드가 빼먹을 수 있음 | DB 트리거가 자동 기록 |

## 구조 — 무엇이 바뀌고 무엇이 그대로인가

```
[지금]  브라우저 ──> Apps Script ──> 구글시트
[이후]  브라우저 ──> Edge Function ──> Postgres
                    (수파베이스)      (수파베이스)
```

**그대로 유지되는 것**
- 깃허브 페이지 호스팅 (주소 그대로)
- 로그인 화면·아이디·비밀번호
- API 모양(`{action: 'upsert', company: {...}}`) → **`app.js`는 거의 안 고침**
- 한글 필드명(`c.업체명`) → 프론트엔드 코드 그대로

**바뀌는 것**
- `Code.gs` (Apps Script) → `index.ts` (Edge Function)
- 구글시트 `업체관리` 탭 → Postgres `업체` 테이블
- `시트정리()` `헤더복구()` `계약복구()` 같은 **응급 복구 함수들은 전부 불필요** → 삭제

### ⚠️ 자체 로그인을 유지할 때 꼭 필요한 것: Edge Function

수파베이스는 보통 브라우저가 DB에 **직접** 접속합니다. 그게 가능한 이유는
수파베이스 Auth가 "지금 누가 접속했는지"를 DB에 알려주고, DB가 그걸로 권한(RLS)을 판단하기 때문입니다.

자체 로그인을 쓰면 DB가 접속자를 알 수 없습니다. 이 상태로 브라우저가 DB에 직접 붙으면
브라우저에 심긴 접속키(공개 정보)만 있으면 **누구나 업체 테이블 전체를 읽고 쓸 수 있습니다.**
지금보다 보안이 나빠집니다.

그래서 **Edge Function을 API 층으로 둡니다.** Apps Script가 하던 역할을 그대로 가져갑니다.
- 브라우저는 Edge Function만 호출 (DB 주소·키를 모름)
- Edge Function이 토큰을 검증하고, 서버 전용 키로 DB에 접근
- `어드민`/`스태프` 권한 판정도 여기서 (지금과 동일)

> 나중에 생각이 바뀌어 수파베이스 Auth로 넘어가면 Edge Function을 걷어내고
> 브라우저가 DB에 직접 붙는 더 단순한 구조로 갈 수 있습니다. 지금 선택이 그 길을 막지는 않습니다.

## 전체 순서

**핵심 원칙: 구글시트를 절대 먼저 지우지 않는다.** 양쪽을 나란히 돌려보고,
숫자가 완전히 일치하는 걸 확인한 다음에 전환합니다.

### 0단계 — 수파베이스 프로젝트 만들기 (직접, 10분)

1. supabase.com 가입 (무료 플랜으로 충분 — 업체 1,100건은 아주 작은 규모)
2. 새 프로젝트 생성
   - Name: `partner`
   - Database Password: **반드시 따로 적어두세요** (분실하면 복구 안 됨)
   - Region: `Northeast Asia (Seoul)` — 가까울수록 빠름
3. 프로젝트가 만들어지면 **Settings → API** 에서 아래 3개를 저에게 알려주세요
   - `Project URL`
   - `anon public` 키
   - `service_role` 키 → **이건 비밀입니다.** 채팅에 붙이지 마시고,
     나중에 Edge Function 설정 화면에 직접 입력하시면 됩니다

### 1단계 — 테이블 만들기 ✅ SQL 준비 완료

`supabase/sql/01_스키마.sql` 전체를 **SQL Editor**에 붙여넣고 RUN 하시면 됩니다.
만드는 것: `업체` / `사용자` / `변경로그` 세 테이블 + 자동 기록 트리거.
여러 번 실행해도 안전하고, 기존 `public` 스키마는 건드리지 않습니다.

> 이 SQL은 로컬 PostgreSQL 16에서 **실제로 실행해 검증했습니다.**
> 중복 거부 · 잘못된 값 거부 · 빈칸 NULL 통일 · 변경로그 자동기록 · 변경없는 저장은 로그 안 남김 — 전부 확인.

이때 같이 들어가는 안전장치:
- `소속원문` **유니크** → 중복 업체 등록 불가
- `업체구분`은 `판매점·협력점·자점`만 허용
- `상태`는 `활성·휴면`만 허용
- `등록일`·`최근개통일`은 `date` 타입
- Y/N 항목은 `'Y' / 'N' / 빈칸` 세 가지만 허용
  (**빈칸과 N은 다르다**는 지금 규칙을 DB가 지켜줍니다)

### 2단계 — 데이터 옮기기

1. 구글시트 `업체관리` 탭 → **파일 → 다운로드 → CSV**
2. 제가 CSV를 받아 점검합니다 (빈 행·중복 `소속원문`·날짜 형식·깨진 값)
3. 문제를 고친 CSV를 드립니다
4. 수파베이스 **Table Editor → 업체 → Import data from CSV**
5. **건수 대조**: 시트 N건 = 테이블 N건 인지 확인. 안 맞으면 멈추고 원인부터 찾습니다

`사용자` 표도 같이 옮깁니다. 비밀번호 해시는 그대로 가져가므로
**직원분들은 기존 비밀번호를 계속 쓰십니다.**

### 3단계 — Edge Function 배포 ✅ 완료

제가 `supabase/functions/api/index.ts` 를 작성합니다.
지금 `Code.gs`의 14개 동작을 **같은 요청 모양으로** 옮깁니다.

```
login · hasUsers · registerFirstAdmin
list · upsert · delete · bulkImport · bulkUpsert · logs
listUsers · createUser · deleteUser · resetPw · changeMyPw
```

빠지는 것: `시트정리` `헤더복구` `계약복구` `병합실행` `일괄현행화` `진단`
→ 전부 시트 구조 때문에 만든 응급 함수라 더 필요 없습니다.

배포 후 Edge Function 설정에 `SERVICE_ROLE_KEY` 와 `AUTH_SECRET` 을 넣으시면 됩니다.

### 4단계 — 프론트엔드 연결 ✅ 완료 (2026-10-15)

`assets/config.js` 의 주소만 Edge Function 주소로 바꿉니다.
`app.js`는 호출 모양이 같아서 손댈 게 거의 없습니다.

- 함수 이름은 수파베이스가 자동으로 붙인 **`dynamic-processor`** (이름은 동작과 무관)
- 주소: `https://iwfiilgjiqkdsuybqwwk.supabase.co/functions/v1/dynamic-processor`
- **되돌리려면** `config.js` 에서 API_URL 두 줄을 맞바꾸고 푸시하면 끝 (옛 앱스크립트 주소를 주석으로 남겨둠)

### 5단계 — 병행 검증 (가장 중요)

전환하기 전에 **반드시** 확인합니다.

- [ ] 전체 업체 수가 시트와 같은가
- [ ] 판매점 / 협력점 / 휴면 수가 같은가
- [ ] 계산서 탭: 정발행·역발행·원천세 수가 같은가
- [ ] 계약 탭: 완료·진행중·발송대기·확인필요 수가 같은가
- [ ] 업체 하나 수정 → 저장 → **새로고침 후에도 남아 있는가**
- [ ] 개통리스트 업로드 → 미리보기 숫자가 시트 때와 같은가
- [ ] 스태프 계정으로 로그인 → 수정 가능 / 계정관리 불가
- [ ] 변경로그에 **이름이 제대로** 찍히는가 (`???` 아님)
- [ ] 정산변환이 계산서형태를 제대로 읽어오는가

### 6단계 — 전환 및 정리

1. 직원분들께 안내 → 재로그인
2. 1~2주 지켜봅니다
3. 문제 없으면 Apps Script 배포를 **중지**(삭제 아님)
4. 구글시트는 **읽기전용 백업**으로 남겨둡니다 (지우지 않습니다)

## 일괄수정은 앞으로 이렇게

1. Table Editor → `업체` → 우측 상단 **Export to CSV**
2. 엑셀에서 고치기 (기호 수십 군데 변경 등)
3. 돌아와서 **Import data from CSV** → 기존 행 덮어쓰기
4. `변경로그`에 자동 기록됩니다

간단한 수정은 테이블 에디터에서 셀을 직접 고쳐도 됩니다 (엑셀처럼 생긴 표입니다).
